================================================================================
          MCP PRACTICE PROJECT - MODE-AWARE ASSISTANT SYSTEM
================================================================================

PROJECT OVERVIEW
================================================================================
This project implements a Model Context Protocol (MCP) server with an LLM-powered
client that features dynamic personality modes. The assistant can switch between
different personalities while maintaining full MCP functionality.

Technologies Used:
- Python 3.x
- Google Gemini API (gemini-2.5-flash)
- OpenAI API (DALL-E for image generation)
- MCP (Model Context Protocol) - FastMCP
- PySerial (for Arduino communication)


================================================================================
AVAILABLE PERSONALITY MODES
================================================================================

1. NORMAL
   - Neutral and helpful assistant (default mode)
   
2. SANTA
   - Warm, cheerful Santa Claus with festive expressions
   - Uses "Ho ho ho!", references Christmas, North Pole, elves, reindeer
   
3. ENGINEER
   - Precise, technical senior software engineer
   - Detail-oriented, focuses on architecture and best practices
   
4. TEACHER
   - Patient, encouraging educator
   - Explains step-by-step, uses analogies, checks for understanding
   
5. PIRATE
   - Friendly pirate with adventurous spirit
   - Uses pirate slang (ahoy, matey, arr), references sea and treasure


================================================================================
MCP SERVER CAPABILITIES
================================================================================

TOOLS (Functions the assistant can call):
------------------------------------------
1. add(a: int, b: int)
   - Adds two numbers together
   
2. control_light(state: str)
   - Controls Arduino light ('on' or 'off')
   - Sends commands via serial port (COM3, 9600 baud)
   
3. create_image(prompt: str)
   - Generates images using OpenAI DALL-E 2
   - Returns markdown link to generated image

RESOURCES (Read-only data sources):
------------------------------------
1. greeting://{name}
   - Returns personalized greeting for given name
   - Example: greeting://Alice -> "Hello, Alice!"
   
2. light://state
   - Returns current light state (on/off)

PROMPTS (Template generators):
-------------------------------
1. check_fact(sentence: str)
   - Generates fact-checking prompt template
   - Mode-aware (adapts to current personality)

================================================================================
KEY IMPLEMENTATION: MODE MANAGER
================================================================================

File: mode_manager.py

Functions:
----------
get_mode() -> str
    Returns the currently active mode name

set_mode(mode_name: str) -> bool
    Sets the active mode, returns True if successful

get_mode_context() -> str
    Returns personality description for current mode
    This is injected into every LLM prompt

list_available_modes() -> list
    Returns list of all available mode names

get_mode_description(mode_name: str) -> str
    Returns description for a specific mode

Architecture:
-------------
- Uses global variable _active_mode to store current state
- Default mode is "normal"
- Mode definitions stored in MODES dictionary
- Case-insensitive mode switching
- Automatic whitespace trimming


================================================================================
HOW MODE SWITCHING WORKS
================================================================================

CLIENT-SIDE IMPLEMENTATION (Critical Fix):
-------------------------------------------
Mode management happens on the CLIENT side (llm_wrapper.py), not the server!

Why?
- Client and server run in SEPARATE processes
- Each has its own copy of mode_manager with separate state
- If server updates mode, client still reads old value
- Solution: Client updates its own mode_manager directly

Implementation in llm_wrapper.py:
----------------------------------
When LLM decides to switch modes:
1. LLM returns: "CALL set_mode mode=santa"
2. llm_wrapper.py intercepts this
3. Calls: mode_manager.set_mode("santa") LOCALLY
4. Returns confirmation to user
5. Next prompt automatically uses new personality

Flow:
-----
User: "Switch to santa mode"
  -> LLM decides: CALL set_mode mode=santa
  -> Client updates local mode_manager
  -> Client confirms: "Mode switched to 'SANTA'..."
  
User: "Hello"
  -> Client reads mode_manager.get_mode() = "santa"
  -> Injects Santa personality into prompt
  -> LLM responds as Santa: "Ho ho ho! Merry Christmas!"


================================================================================
PROMPT STRUCTURE (HOW PERSONALITY IS INJECTED)
================================================================================

Every LLM request follows this structure:

=== YOUR PERSONALITY (ALWAYS MAINTAIN THIS) ===
[Mode personality description from mode_manager]
=== END PERSONALITY ===

You are connected to an MCP server.

The available capabilities are:
[List of tools, resources, prompts...]

Response rules:
- For math: CALL add a=X b=Y
- For images: CALL create_image prompt=...
- For mode switching: CALL set_mode mode=...
- Otherwise: NO TOOL NEEDED <reply IN CHARACTER>

IMPORTANT: When giving direct responses, you MUST stay fully in character
according to your personality context at the top. This is critical!

USER: [user input]

Key Design Decisions:
---------------------
1. Personality section has visual markers (===) to stand out
2. Explicit "ALWAYS MAINTAIN THIS" directive
3. Repeated reminder to stay "IN CHARACTER"
4. Multiple reinforcement points throughout prompt
5. Personality context fetched fresh on every request

================================================================================
ADDING NEW MODES
================================================================================

To add a new personality mode:

1. Open mode_manager.py

2. Add entry to MODES dictionary:

MODES = {
    "normal": "You are a neutral and helpful assistant.",
    "santa": "...",
    # Add your new mode here:
    "wizard": (
        "You are Gandalf the Wise - mysterious, powerful, and ancient. "
        "You speak with wisdom and occasionally use magical references."
    ),
}

3. Save the file - new mode is immediately available!

4. Test it:
   You: Switch to wizard mode
   Bot: Mode switched to 'WIZARD'...
   
   You: Hello
   Bot: Greetings, traveler. What wisdom do you seek?


================================================================================
CRITICAL BUGS FIXED DURING DEVELOPMENT
================================================================================

Bug #1: Weak Personality Expression
------------------------------------
Problem:
- Personality was being diluted by technical MCP instructions
- LLM saw 2 lines of personality + 20 lines of technical details
- Result: Weak character portrayal

Solution:
- Added visual markers: === YOUR PERSONALITY (ALWAYS MAINTAIN THIS) ===
- Added explicit in-character reminders throughout prompt
- Changed "your direct reply" to "your direct reply IN CHARACTER"
- Multiple reinforcement points

Bug #2: Mode Not Persisting (Critical)
---------------------------------------
Problem:
- User switches to Santa mode
- Server confirms: "Mode switched to 'SANTA'"
- Next message still uses Normal personality
- Debug showed: mode = "normal" after switching to "santa"

Root Cause:
- Client and server are SEPARATE PROCESSES
- Each has its own mode_manager with separate state
- set_mode called on SERVER's mode_manager
- LLM prompts read from CLIENT's mode_manager
- They don't share state!

Solution:
- Moved mode management to CLIENT-SIDE
- llm_wrapper.py now updates its own mode_manager locally
- No more MCP tool calls for mode switching
- Client reads and writes to same mode_manager instance
- State consistency maintained!

Before Fix:
-----------
User: "Switch to santa"
  -> Client calls server's set_mode tool
  -> Server's mode_manager = "santa"
  -> Client's mode_manager = "normal" (unchanged!)
  -> Next prompt uses "normal" personality

After Fix:
----------
User: "Switch to santa"
  -> Client updates own mode_manager = "santa"
  -> Next prompt reads same mode_manager = "santa"
  -> Correct personality used!

================================================================================
TROUBLESHOOTING
================================================================================

Mode not switching?
-------------------
- Verify you're using llm_client.py (not directly calling server)
- Check that mode_manager.py is in same directory
- Restart the client if mode seems stuck

Personality weak?
-----------------
- This is normal for subtle personalities
- Consider strengthening mode descriptions in mode_manager.py
- Add more specific phrases and examples

Arduino not responding?
-----------------------
- Check COM port (default: COM3)
- Verify baud rate (default: 9600)
- System falls back to dummy serial if port unavailable

Image generation fails?
-----------------------
- Verify OpenAI API key is valid
- Check API quota/credits
- Try DALL-E 2 instead of DALL-E 3
- Check error traceback for details
